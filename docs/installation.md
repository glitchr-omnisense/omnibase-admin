# Installation

## Requirements

What `composer.json` requires: PHP 8.1 or later, `symfony/config`,
`dependency-injection`, `http-kernel` and `form` 6, 7 or 8, `omnibridge/symfony`
1.x and `omnisense/omnibase` 3.0 or 4.0.

## The bundle

```bash
composer require omnibase/admin
```

```php
// config/bundles.php
return [
    // ...
    Base\BaseBundle::class => ['all' => true],
    Base\Admin\AdminBundle::class => ['all' => true],
];
```

`AdminBundle::getPath()` is the package's root: its `templates/` is the `@Admin`
namespace. Like `BaseBundle`, it aliases each of its controllers
`Base\Admin\Controller\X` to `App\Admin\Controller\X` unless the application
declares a class there: an application overrides a screen by writing that class.

## The routes

The CRUDs' routes are generated by the loader of type `base_admin`
(`Base\Admin\Router\AdminRouteLoader`); import it after the core's controllers:

```yaml
# config/routes.yaml
base_controller:
    resource: "@BaseBundle/Controller"
    type: attribute
    prefix: /

# The back office's CRUDs (omnibase/admin), /admin.
base_admin_crud:
    resource: .
    type: base_admin
```

The prefix is `/admin` (`AdminRouteRegistry`'s `$urlPrefix`). The loader adds
the system pages, the dashboard's widget and layout endpoints, the trash, the
revisions, the opening hours, and - when the dashboard controller has no
`#[Route]` of its own - the route `admin` on the prefix. An application's
routes imported after it keep their names over the loader's. Every route is in
the [Reference](reference.md#routes).

## The dashboard controller

The back office's front door is the application's: a class extending
`Base\Admin\Controller\AbstractDashboardController` (autoconfigured, tagged
`base.admin.dashboard_controller`). The harness's (`docker/app/src/Controller/Admin/DashboardController.php`
in omnisense/omnibase):

```php
namespace App\Controller\Admin;

use Base\Admin\Config\MenuItem;
use Base\Admin\Controller\AbstractDashboardController;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Routing\Attribute\Route;

class DashboardController extends AbstractDashboardController
{
    #[Route('/admin', name: 'admin')]
    public function index(): Response
    {
        return parent::index();
    }

    public function configureWidgetItems(): iterable
    {
        yield MenuItem::section('Members and the site', 'fa-solid fa-users')->setSubItems([
            MenuItem::linkToCrud(\Base\Entity\User::class, 'Accounts', 'fa-solid fa-user'),
            MenuItem::linkToCrud(\Base\Entity\Layout\Setting::class, 'Settings', 'fa-solid fa-sliders'),
            MenuItem::linkToRoute('admin_trash', [], 'Trash', 'fa-solid fa-trash-can'),
        ]);
    }
}
```

See [The dashboard and the menu](dashboard.md).

## Who enters

On every page of the back office (and of the profiler) the core's
`SecuritySubscriber` asks `isGranted('BACKEND')`, which the core's `AdminVoter`
grants to a signed-in `ROLE_ADMIN`. What each CRUD then lets an administrator do
is in [Who may write in a CRUD](crud-access.md).

## Contextual help

The help panel of the back office shows the manuals of
[omnibase/docs](https://github.com/glitchr-omnisense/omnibase-docs) when it is installed.
